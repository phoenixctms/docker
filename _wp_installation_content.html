Installation

The Phoenix CTMS is an extensive application dedicated to run on enterprise hardware to serve many users. If you want to take a look and try it, the easiest path is Docker Compose (Windows, macOS, or Linux). No VirtualBox and no hour-long on-host Maven build are required (about 6–8 GB RAM recommended).

Docker Compose (recommended)

  1. Install Docker Desktop (Windows/macOS) or Docker Engine + Compose (Linux).
  2. Clone and start the evaluation stack from phoenixctms/docker: 
    git clone https://github.com/phoenixctms/docker.git
cd docker
docker compose build
docker compose up -d
docker compose logs -f db-seed
  3. When seeding finishes, open http://localhost:8888 and log in with the printed phoenix credentials.
  4. Optional demo data on first start: set SEED_DEMO_DATA=true before docker compose up, or see the repo README.

Full details, environment variables, and reset commands are in the docker repository README.

Virtual machine (.ova) alternative

If you prefer a full Debian appliance instead of Docker, use the automated .ova bootstrap (same hardware guidance: ~6 GB RAM, some free disk, 2 CPU cores).

  1. Download and install a virtualization software package supporting .ova (Open Virtual Appliances) files. Oracle VM VirtualBox or VMware Workstation/Player are known to work and are available for various operating systems.
  2. Download deb_13_3_phoenix.ova. It is a vanilla Debian 13 (Linux) virtual machine image without base packages but a bootstrap script placed to launch the Phoenix CTMS installation procedure.
  3. Open .ova with the virtualization software, and power on the virtual machine.
  4. Network connectivity is vital for installation and operation. The virtual machine uses a bridged network interface, which obtains its own IP address via DHCP. When prompted regarding the unknown preset network interface, just change it to the one available on your computer, which is suggested by default.
  5. After startup, the linux console shows the standard login prompt. Login once with username phoenix, password phoenix. The installation procedure will start immediately and therefore requires confirmation by providing the password phoenix one more time.
  6. The installation procedure will take around an hour to download, build and install from most recent upstream sources (Debian console can fade after some time). When finished, a default application user is provisioned and its credentials are printed to the console.
  7. You might want to change the provided password right after logging in using your favourite browser. Note when opening the application URL the first time, you need to allow the browser accepting the self-signed certificate. It is also required to not block pop-ups (browser tabs).

You can also install on a bare Debian/Ubuntu host with install-debian / install.sh (see the main ctsms README).

Generating Demo Data

On the virtual machine / Debian install, you can populate the system with demo data by executing the command below in the linux console.

This demo data generator simulates user entries for use cases and work flows that

  1. qualified for test coverage during a risk assessment,
  2. require proof of constant response times in large volume scenarios,
  3. ... and to provide data to play with and help you to get an idea on how the system works.

Running the generator effectively adds several departments with random names and items for each:

  • Hierarchy of inventory items
  • Hierarchy of staff persons with realistic names (german) and organisations
  • Application users linked to created persons/organisations
  • Courses with renewal hierarchy, participation workflow simulation
  • Input fields for sample inquiry forms, eCRFs and custom subject list data
  • Example sketch input fields: VAS (visual analogue scale), DAS-28 (disease activity score) joint selector
  • Subjects with realistic names (german) and gender/age distribution, data entry for a diabetology sample inquiry form
  • Trials: visit schedule, staff duties, inquiry forms, subject groups, subject selection and enrollment workflow simulation, custom subject list data
  • eCRF with series sections and basic form scripting examples (multivariate edit checks/calculations)
  • Volume test of empty .pdf documents, stored per inventory items, persons, organisations ...
  • Basic queries without any filter criteria to list all created users, inventory items, persons, organisations ...

You can log in with any of the generated application users (the random username equals its password) and will see the perspective of that user.
